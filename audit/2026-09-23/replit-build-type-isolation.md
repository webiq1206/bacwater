# Replit build fix: stale development route types

Date: September 23, 2026. Baseline main: b13b0862c7715d2afcd90c4527fe0103894da337.

## Observed failure

The supplied deployment log completed dependency installation, Prisma generation, schema synchronization, editorial-default updates, all six assertion suites and Webpack compilation. TypeScript then failed inside .next/dev/types/validator.ts with TS2344 and TS2307. The development artifacts still referenced the removed /plan/advanced and /tools/ml-to-units page/layout modules. Those URLs intentionally remain redirects in next.config.ts; restoring obsolete pages is not the remedy.

The shared tsconfig.json included both production and development generated types. Clean CI checkouts did not contain the stale development artifacts present in the Replit workspace, so the previous clean-build tests did not reproduce the deployment failure.

## Change

Next.js now selects tsconfig.json for its development-server phase and tsconfig.build.json for production build, type generation and production-server phases. The production configuration inherits the existing strict compiler settings, source inclusions and current production route types, but excludes only node_modules and .next/dev. Standalone production TypeScript checks use a separate incremental-state path.

There is no error suppression, application route removal, cache-directory deletion, dependency upgrade, production data change or change to the configured Replit build command in this patch. Development output may remain on disk without becoming a production compilation input. next-env.d.ts remains generated by Next.js rather than committed or edited as a permanent fix.

## Reproduction and regression coverage

The added script runs only its fixture-creation phase in a disposable CI checkout. It installs stale generated development types for the exact retired routes and an ignored next-env.d.ts pointing at development types. CI then runs the real npm production build without deleting those files.

After the build, the script checks the effective production configuration, full TypeScript file graph and regenerated next-env reference. It proves that the shared development configuration still rejects the same TS2344/TS2307 fixture, while the production configuration excludes it. Negative controls temporarily introduce a real source type error and a broken current production route import; both must still fail before the controls are removed in finally blocks.

Local validation reproduced the original errors and passed production type generation plus strict production typechecking with the stale artifacts retained. The final commit's GitHub Actions results are the acceptance record for the full production build, type-isolation regression, existing browser/privacy/content suites and consent suite. A test-environment pass does not establish successful Replit publication.

## Publication

Pull the corrected main into the Replit workspace without overwriting unrelated changes, then Republish. There is no need to recreate the redirected pages or manually delete generated files. The earlier deployment log already shows database synchronization and matched editorial updates succeeded before the TypeScript failure; do not reseed production to address this build error.
