# Shared session inputs and explicit amount/timing

Scope: current-tab drafts across the live hero, dedicated single-compound product calculators, mass-based compound references, BAC water tool, guided/new plan forms, reverse calculation and inventory. The mg/mcg and U-100 converters have separate like-for-like session stores shared with the hero tabs. Blends, prepared solutions, water-supply counts and product IU stay isolated. Saved-plan edits use plan-specific draft scopes and do not overwrite the working calculation. Existing saved-plan storage and access control are unchanged.

Each time and Whole week are explicit, visible choices. Frequencies use only the visitor's instructions. Each-time amounts remain unchanged when frequency changes; weekly totals divide into the chosen number of equal uses. Daily means seven uses per week in this arithmetic model. Weekly totals require a count; unequal amounts need separate each-time calculations. Unit changes preserve mass. Results explain concentration, each-use mL/U-100 volume and the weekly relationship separately. No product-based amount, dosing interval, dilution or expiry is generated.

The shared store writes synchronously on input, survives route changes and refresh in the same tab, and keeps raw incomplete entries without treating them as valid numbers. A clear replaces the draft rather than falling back to stale per-product data. Only a previous same-tab hero record is migrated; historical device-wide drafts are not guessed as today's calculation. When storage is blocked, client-side navigation uses memory; reload persistence cannot be promised. No amounts are added to URLs, analytics, affiliate links or server requests except the existing explicit Save action.

Existing per-use/weekly arithmetic is adapted to the saved-plan format without a database migration. No dependency, lockfile, deployment-safety, production database or supplier attribution changes. Current tab storage follows MDN sessionStorage documentation; UI uses React useSyncExternalStore with an empty server snapshot. References: https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage and https://react.dev/reference/react/useSyncExternalStore .

Verification includes pure schedule/conversion and store tests; real hero-to-product, product-to-product, guided-plan, Back, refresh, clear, scope isolation, blocked-storage and responsive/keyboard journeys. Existing assertions were updated to the explicit controls, not removed to hide failures. Exact results are recorded in CI artifacts. Browser emulation is not certification of every physical keyboard, screen reader or clinical regimen.
