# Replit blocked-package build fix

## Observed failure

The owner's September 24, 2026 deployment log shows npm E403 for next-16.3.5.tgz from Replit's package firewall, with the reason Critical CVE. This occurs while installing dependencies, before compiling the application. A successful GitHub build or an empty npm advisory result does not prove that a package satisfies Replit's policy.

## Reviewed security release

The Next.js September 22 security announcement and GHSA-vcvr-r3jv-pc5j identify Next.js versions >=16.2.0 <16.3.6 as affected by CVE-2026-94545 in the Node.js ImageResponse implementation. The published patch is 16.3.6. Exposure depends on passing attacker-controlled values into generated SVG content, attributes or styles; the package-block message alone is not evidence that this application was exploited.

Sources checked September 24, 2026:

## Changes

- Pin next to 16.3.6.
- Regenerate package-lock.json with npm. Only the root package record, Next, @next/env and the eight @next/swc platform entries changed. URLs and integrity values were generated by npm, not invented or copied from the blocked release.
- Retain the existing font-header compatibility fix. The reviewed v16.3.6 source still has the extension-only URL assumption. Update the exact version guard for the patched release, keep the source-shape assertion and test invalid font headers, and never modify next/og or its security dependencies.
- Add scripts/verify-next-security.mjs to normal postinstall and test execution. The manifest, lockfile, installed Next version and framework companion versions must agree with the reviewed patch, even when npm audit has not yet indexed the advisory.

No registry override, security-policy exception, firewall bypass, production database change, schema operation or application redesign was added. The affiliate directory, product links, calculator behavior, account flows and existing Replit build command are unchanged.

## Release verification and publication boundary

The final pull request must pass the existing typecheck, production build, consent, hero, content, calculator, product-directory, account and browser regression workflows. Their actual execution results and the tested commit belong in the final PR verification record; the presence of tests alone is not a claim that they passed.

After merge, pull the updated main branch into the existing Replit workspace and republish. A successful GitHub test build cannot certify a successful Replit publication or the current status of Replit's private package policy. No claim of live publication is made by this code change. If the same old tarball appears again, check the workspace's package.json and package-lock.json before retrying.
