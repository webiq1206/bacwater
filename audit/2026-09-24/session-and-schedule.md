# Shared calculator sessions and explicit amount schedules

Implements the owner's two latest requests: preserve entered data through the homepage, product selection and compatible tools; make the difference between an amount each time and an amount for a whole week unmistakable.

The versioned tab-session store is shared by the hero, single-compound product and reference calculators, guided/all-at-once planner, and relevant amount/volume utilities. Writes occur synchronously in input handlers so selecting a product immediately after typing does not outrun an effect. Fullscreen and inline hero views read the same values. Independent converters retain their own quantities. Saved-plan editing is initialized from the saved record, never an unrelated session. Clear removes the connected active mass calculation, not saved plans. Old device-wide drafts are not silently loaded into a new tab.

IU, ingredient-by-ingredient blends, ready-made solutions and water inventory are intentionally separate calculation families. Their own drafts survive returning in the same tab, but a mass or concentration from another family is not copied into an unlike field. Raw calculator values are not put in URLs, analytics or external requests. Blocked session storage falls back to in-memory app navigation; it cannot survive a hard reload without browser storage. Browser session restoration follows the browser's own sessionStorage behavior.

The amount step asks what the user's instructions mean: Each time or Whole week. The amount field is labeled accordingly. Frequency is explicit (no schedule, once/twice/three times weekly, once/twice daily, or a user-entered whole count per week). Daily means seven occasions for arithmetic, not a recommended regimen. Per-occasion input remains unchanged when frequency changes; a weekly input is divided by the count. The display shows each-time amount, weekly total and the multiplication/division. Switching units preserves mass; switching time basis preserves per-occasion mass when the entered count makes that possible, or clears the ambiguous amount with an explanation. Unequal schedules require separate calculations, not an invented average. Existing backend limits and normalized weekly-total storage remain intact without schema changes.

Local TypeScript, existing pure assertions, design checks and 16 new session/schedule groups passed before browser verification. Added acceptance exercises hero-to-product handoff, frequency semantics, refresh/Back, clear, independent tabs, compatible utilities, isolated IU/solution/blend drafts, blocked storage and enlarged text in Chromium/WebKit. All retained workflows are required before merge. Any final CI failures must be addressed, not bypassed.

No database schema, lockfile, dependency, Replit configuration, supplier attribution or production database operation is part of this change. Publishing and physical-device acceptance remain separate from Git delivery. This release does not assert that unrelated master-audit tasks are complete.

Technical references consulted: MDN Window.sessionStorage and W3C WAI Forms grouping/instructions/notifications tutorials. User-entered amounts and frequencies are arithmetic inputs, not dosing advice.
